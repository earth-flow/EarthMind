In general, environment variables, like `EARTHMIND_PORT` or `EARTHMIND_LOG_LEVEL`, configure how EarthMind runs.
These are broad settings that apply to your entire EarthMind deployment.

In contrast, global variables are user-defined values stored in EarthMind's database for use in flows, such as `OPENAI_API_KEY`.
EarthMind can also source global variables from environment variables.
For more information, see [EarthMind global variables](/configuration-global-variables).

## Configure environment variables for EarthMind OSS

EarthMind recognizes [supported environment variables](#supported-variables) from the following sources:

- Environment variables set in your terminal.
- Environment variables imported from a `.env` file when starting EarthMind.
- Environment variables set with the [EarthMind CLI](./configuration-cli), including the `--env-file` option and direct options, such as `--port`.

You can choose to use one or more of these sources.

### Precedence {#precedence}

If the same environment variable is set in multiple places, the following hierarchy applies:

1. EarthMind CLI options override all other sources.
2. The `.env` file overrides system environment variables.
3. System environment variables are used only if not set elsewhere.
When running a EarthMind Docker image, the `-e` flag can be used to set additional system environment variables.

For example:

* If you set `EARTHMIND_PORT=8080` in your system environment and `EARTHMIND_PORT=7860` in `.env`, EarthMind uses `7860` from `.env`.
* If you use the EarthMind CLI to run `earthmind run --env-file .env --port 9000`, and you set `EARTHMIND_PORT=7860` in `.env`, then EarthMind uses `9000` from the CLI option.

### Set environment variables in your terminal {#configure-variables-terminal}

Run the following commands to set environment variables for your current terminal session:

<Tabs>
<TabItem value="linux-macos" label="Linux or macOS" default>

```bash
export VARIABLE_NAME='VALUE'
```

</TabItem>
<TabItem value="windows" label="Windows">

```
set VARIABLE_NAME='VALUE'
```

</TabItem>
<TabItem value="docker" label="Docker">

```bash
docker run -it --rm \
    -p 7860:7860 \
    -e VARIABLE_NAME='VALUE' \
    earthmindai/earthmind:latest
```

</TabItem>
</Tabs>

When you start EarthMind, it looks for environment variables that you've set in your terminal.
If it detects a supported environment variable, then it automatically adopts the specified value, subject to [precedence rules](#precedence).

### Import environment variables from a .env file {#configure-variables-env-file}

1. If EarthMind is running, quit EarthMind.

2. Create a `.env` file, and then open it in your preferred editor.

3. Define [EarthMind environment variables](#supported-variables) in the `.env` file.

    <details>
    <summary>Example: .env</summary>

    ```text
    DO_NOT_TRACK=True
    EARTHMIND_AUTO_LOGIN=False
    EARTHMIND_AUTO_SAVING=True
    EARTHMIND_AUTO_SAVING_INTERVAL=1000
    EARTHMIND_BACKEND_ONLY=False
    EARTHMIND_BUNDLE_URLS=["https://github.com/user/repo/commit/hash"]
    EARTHMIND_CACHE_TYPE=async
    EARTHMIND_COMPONENTS_PATH=/path/to/components/
    EARTHMIND_COMPONENTS_INDEX_PATH=/path/to/component_index.json
    EARTHMIND_CONFIG_DIR=/path/to/config/
    EARTHMIND_DATABASE_URL=postgresql://user:password@localhost:5432/earthmind
    EARTHMIND_DEV=False
    EARTHMIND_FALLBACK_TO_ENV_VAR=False
    EARTHMIND_HEALTH_CHECK_MAX_RETRIES=5
    EARTHMIND_HOST=localhost
    EARTHMIND_LANGCHAIN_CACHE=InMemoryCache
    EARTHMIND_MAX_FILE_SIZE_UPLOAD=10000
    EARTHMIND_MAX_ITEMS_LENGTH=100
    EARTHMIND_MAX_TEXT_LENGTH=1000
    EARTHMIND_LOG_LEVEL=error
    EARTHMIND_OPEN_BROWSER=False
    EARTHMIND_PORT=7860
    EARTHMIND_REMOVE_API_KEYS=False
    EARTHMIND_SAVE_DB_IN_CONFIG_DIR=True
    EARTHMIND_SECRET_KEY=somesecretkey
    EARTHMIND_STORE_ENVIRONMENT_VARIABLES=True
    EARTHMIND_SUPERUSER=adminuser
    EARTHMIND_SUPERUSER_PASSWORD=adminpass
    EARTHMIND_WORKER_TIMEOUT=300
    EARTHMIND_WORKERS=3
    ```

    For additional examples, see [`.env.example`](https://github.com/earthmind-ai/earthmind/blob/main/.env.example) in the EarthMind repository.

    </details>

4. Save and close `.env`.

5. Start EarthMind with your `.env` file:

    <Tabs>
    <TabItem value="local" label="Local" default>

    ```bash
    uv run earthmind run --env-file .env
    ```

    </TabItem>
    <TabItem value="docker" label="Docker">

    ```bash
    docker run -it --rm \
        -p 7860:7860 \
        --env-file .env \
        earthmindai/earthmind:latest
    ```

    </TabItem>
    </Tabs>

    If your `.env` file isn't in the same directory, provide the path to your `.env` file.

On startup, EarthMind imports the environment variables from your `.env` file, as well as any others that you set in your terminal, and then adopts their specified values.

## Set environment variables for EarthMind Desktop

Environment variables set in your terminal aren't automatically available to GUI-based applications like EarthMind Desktop when you launch them from the Windows or macOS GUI.

To modify environment variables for EarthMind Desktop, set environment variables in a Desktop `.env` file, and then restart the app.

<Tabs>
<TabItem value="macos" label="macOS" default>

To modify the macOS `.env` file, do the following:

1. Create or edit `~/.earthmind/data/.env`.
2. Add your EarthMind environment variables, for example:

    ```text
    EARTHMIND_LOG_LEVEL=info
    EARTHMIND_DOCLING=true
    ```

3. Save the file.
4. Restart EarthMind Desktop.

</TabItem>
<TabItem value="windows" label="Windows .env file">

To modify the Windows `.env` file, do the following:

1. Create or edit `%APPDATA%\com.EarthMindDesktop\data\.env`.
2. Add your EarthMind environment variables, for example:

    ```text
    EARTHMIND_LOG_LEVEL=info
    EARTHMIND_DOCLING=true
    ```

3. Save the file.
4. Restart EarthMind Desktop.

</TabItem>
<TabItem value="windows-user-vars" label="Windows user environment variables">

Windows supports two sources for EarthMind Desktop environment variables: a EarthMind application `.env` file, and Windows user environment variables.

The `.env` file at `%APPDATA%\com.EarthMindDesktop\data\.env` is the recommended approach, but
Windows user variables are useful for single-sourcing API keys between EarthMind and other Windows applications.
If the same variable is defined in both the EarthMind application `.env` file and as a Windows user environment variable, the `.env` file takes precedence.

To modify the Windows user environment variables, do the following:

1. Press <kbd>Win + R</kbd>, enter `sysdm.cpl`, and then press <kbd>Enter</kbd>.
2. Click the **Advanced** tab, and then click **Environment Variables**.
3. In **User variables**, click **New**.
4. Enter the variable name, such as `OPENAI_API_KEY`, and its value.
5. Click **OK**, and then **restart EarthMind Desktop**.

</TabItem>
</Tabs>

### Server

The following environment variables set base EarthMind server configuration, such as where the server is hosted, required files for SSL encryption, and the deployment type (frontend and backend, backend-only, development mode).

| Variable | Format | Default | Description |
|----------|--------|---------|-------------|
| `EARTHMIND_HOST` | String | `localhost` | The host on which the EarthMind server will run. |
| `EARTHMIND_PORT` | Integer | `7860` | The port on which the EarthMind server runs. The server automatically selects a free port if the specified port is in use. |
| `EARTHMIND_BACKEND_ONLY` | Boolean | `False` | Run only the EarthMind backend service (no frontend). |
| `EARTHMIND_DEV` | Boolean | `False` | Whether to run EarthMind in development mode (may contain bugs). |
| `EARTHMIND_OPEN_BROWSER` | Boolean | `False` | Open the system web browser on startup. |
| `EARTHMIND_HEALTH_CHECK_MAX_RETRIES` | Integer | `5` | Set the maximum number of retries for EarthMind's server status health checks. |
| `EARTHMIND_WORKERS` | Integer | `1` | Number of worker processes. See [Deploy EarthMind with multiple workers](./deployment-multi-worker#recommended-gunicorn-settings). |
| `EARTHMIND_WORKER_TIMEOUT` | Integer | `300` | Worker timeout in seconds. See [Deploy EarthMind with multiple workers](./deployment-multi-worker#recommended-gunicorn-settings). |
| `EARTHMIND_GUNICORN_PRELOAD` | Boolean | `False` | Enables Gunicorn `preload_app`. Non-Windows only. See [Deploy EarthMind with multiple workers](./deployment-multi-worker#recommended-gunicorn-settings). |
| `EARTHMIND_JOB_QUEUE_TYPE` | String | `asyncio` | Job queue backend. Use `redis` for multi-worker deployments. See [Deploy EarthMind with multiple workers](./deployment-multi-worker#configuration-reference). |
| `EARTHMIND_SSL_CERT_FILE` | String | Not set | Path to the SSL certificate file for enabling HTTPS on the EarthMind web server. This is separate from [database SSL connections](/configuration-custom-database#connect-earthmind-to-a-local-postgresql-database). |
| `EARTHMIND_SSL_KEY_FILE` | String | Not set | Path to the SSL key file for enabling HTTPS on the EarthMind web server. This is separate from [database SSL connections](/configuration-custom-database#connect-earthmind-to-a-local-postgresql-database). |
| `EARTHMIND_DEACTIVATE_TRACING` | Boolean | `False` | Deactivate tracing functionality. |
| `EARTHMIND_CELERY_ENABLED` | Boolean | `False` | Enable Celery for distributed task processing. |
| `EARTHMIND_ALEMBIC_LOG_TO_STDOUT` | Boolean | `False` | Whether to log Alembic database migration output to stdout instead of a log file. If `true`, Alembic logs to `stdout` and the default log file is ignored. |

| `EARTHMIND_CREATE_STARTER_PROJECTS` | Boolean | `True` | Whether to create templates during initialization. If `false`, EarthMind doesn't create templates, and `EARTHMIND_UPDATE_STARTER_PROJECTS` is treated as `false`. |

| `EARTHMIND_LAZY_LOAD_COMPONENTS` | Boolean | `False` | If `true`, EarthMind only partially loads components at startup and fully loads them on demand. This significantly reduces startup time but can cause a slight delay when a component is first used. |
| `EARTHMIND_EVENT_DELIVERY` | String | `streaming` | How to deliver build events to the frontend: `polling`, `streaming` or `direct`. |
| `EARTHMIND_FRONTEND_PATH` | String | `./frontend` | Path to the frontend directory containing build files. For development purposes only when you need to serve specific frontend code. |

| `EARTHMIND_MAX_TEXT_LENGTH` | Integer | `1000` | Maximum number of characters to store and display in the visual editor. Responses longer than this will be truncated when displayed in the visual editor. Doesn't truncate outputs or responses passed between components. |

### Hide UI elements with embedded mode {#embedded-mode}

When you embed the EarthMind visual editor in another application, such as an iframe within a host portal, you can hide UI elements that are usually visible in the visual editor.

The embedded mode environment variables control which UI elements appear in the visual editor.
Embedded mode controls UI visibility only, and does not block API endpoints or deploy EarthMind.

Embedded mode is distinct from the [embedded chat widget](/concepts-publish#embedded-chat-widget), which embeds a single flow's chat UI in a website.

When `EARTHMIND_EMBEDDED_MODE=true`, EarthMind hides the following buttons in the UI:

* **Logout**
* **New project**
* **New flow**
* **Starter projects**

You can hide individual elements without enabling the umbrella flag.

| Variable | Format | Default | Description |
|----------|--------|---------|-------------|
| `EARTHMIND_EMBEDDED_MODE` | Boolean | `False` | Umbrella flag for embedded or iframe deployments. When `true`, hides standalone UI elements: logout, new project, new flow, and starter projects. Individual hide flags can also be set without enabling this flag. |
| `EARTHMIND_HIDE_LOGOUT_BUTTON` | Boolean | `False` | If `true`, hides the logout button in the account menu. Automatically enabled when `EARTHMIND_EMBEDDED_MODE=true`. |
| `EARTHMIND_HIDE_NEW_PROJECT_BUTTON` | Boolean | `False` | If `true`, hides the new project/folder button in the sidebar. Automatically enabled when `EARTHMIND_EMBEDDED_MODE=true`. |
| `EARTHMIND_HIDE_NEW_FLOW_BUTTON` | Boolean | `False` | If `true`, hides the new flow button in the header. Automatically enabled when `EARTHMIND_EMBEDDED_MODE=true`. |
| `EARTHMIND_HIDE_STARTER_PROJECTS` | Boolean | `False` | If `true`, hides the starter projects tab in the templates modal. Does not affect database seeding of starter projects. Automatically enabled when `EARTHMIND_EMBEDDED_MODE=true`. |
| `EARTHMIND_HIDE_GETTING_STARTED_PROGRESS` | Boolean | `False` | If `true`, hides the getting-started onboarding progress UI. Not automatically enabled when `EARTHMIND_EMBEDDED_MODE=true`. |
