The Terraflow command line interface is the main interface for managing and running the Terraflow server.

The Terraflow CLI is automatically installed when you [install the Terraflow package](/get-started-installation).
It isn't available for Terraflow Desktop.

## How to use the CLI

The Terraflow CLI can be invoked in several ways, depending on your installation method and environment.

The recommended approach is to run the CLI with `uv run` from within a virtual environment where Terraflow is installed.

For example, to start Terraflow on the default port, run the following command:

    ```bash
    uv run terraflow run
    ```

If Terraflow is installed globally or added to your PATH, you can execute the CLI directly with `terraflow`.

    ```bash
    terraflow run
    ```

## Precedence

Terraflow CLI options override the values of [environment variables](/environment-variables) set in your terminal or primary `.env` file.

For example, if you have `TERRAFLOW_PORT=7860` defined as an environment variable, and you run the CLI with `--port 7880`, then Terraflow sets the port to `7880` because the CLI option overrides the environment variable.

This also applies to Boolean environment variables.
For example, if you set `TERRAFLOW_REMOVE_API_KEYS=True` in your `.env` file, you can change it to `False` at runtime by running the CLI with `--no-remove-api-keys`.

## Terraflow CLI options

All Terraflow CLI commands support options that modify the command's behavior or set environment variables.

To set values for options, you can use either of the following syntax styles:

* `--option value`
* `--option=value`

Values with spaces must be surrounded by quotation marks:

* `--option 'Value with Spaces'`
* `--option="Value with Spaces"`

### Boolean options

Boolean options enable and disable settings.
They have a true (enabled) and false (disabled) form:

* Enabled (true): `--option`
* Disabled (false): `--no-option`

The following examples compare Boolean option forms for `REMOVE_API_KEYS`.

<Tabs>
<TabItem value="true" label="True" default>

`--remove-api-keys` is equivalent to setting `TERRAFLOW_REMOVE_API_KEYS=True` in `.env`:

```bash
uv run terraflow run --remove-api-keys
```

</TabItem>
<TabItem value="false" label="False">

`--no-remove-api-keys` is equivalent to `TERRAFLOW_REMOVE_API_KEYS=False` in `.env`:

```bash
uv run terraflow run --no-remove-api-keys
```

</TabItem>
</Tabs>

In the following command references, default values for Booleans include both the CLI flag and the equivalent Boolean evaluation, such as "`--option` (true)" and "`--no-option` (false)".

### Universal options

The following options are available for all Terraflow CLI commands:

* `--version`, `-v`: Show the version and exit.
* `--install-completion`: Install auto-completion for the current shell.
* `--show-completion`: Show the location of the auto-completion config file, if installed.
* `--help`: Print information about command usage, options, and arguments.

### terraflow copy-db

Copies the Terraflow database files from the cache directory to the current Terraflow installation directory, which is the directory containing `__main__.py`.
You can find the copy target directory by running `which terraflow`.

The following files are copied if they exist in the cache directory:

* `terraflow.db`: The main Terraflow database, stored in the user cache directory
* `terraflow-pre.db`: The pre-release database, if it exists

### terraflow migration

Manages Terraflow database schema changes using [Alembic](https://alembic.sqlalchemy.org/en/latest/), a database migration tool for SQLAlchemy.

The `migration` command has two modes:

* **Test mode (default)**: Checks if migrations can be applied safely without actually running the migrations.
Use this mode to previews the changes that would be made to the database schema before proceeding with the migrations.

* **Fix mode**: Applies the migrations to update the database schema.

    :::warning
    `terraflow migration --fix` is a destructive operation that can delete data.
    Always run `terraflow migration` first to preview the changes.
    :::

<Tabs groupId="Invocation">
  <TabItem value="uv (recommended)" label="uv (recommended)" default>

1. Run test mode:

  ```bash
  uv run terraflow migration
  ```

2. Preview the changes returned by the test to determine if it's safe to proceed with the migration.

3. Run fix mode to apply the changes:

  ```bash
  uv run terraflow migration --fix
  ```

  </TabItem>
  <TabItem value="Global" label="Global">


#### Options

This command supports some common and non-sensitive configuration options for your Terraflow server.
Other options must be set in the `.env` or your terminal.
For more information Terraflow configuration options, see [Terraflow environment variables](/environment-variables).

| Option | Default | Type | Description |
|--------|---------|--------|-------------|
| `--auto-saving` | `--auto-saving` (true) | Boolean | Whether to enable flow auto-saving in the visual editor. Use `--no-auto-saving` to disable flow auto-saving. |
| `--auto-saving-interval` | `1000` | Integer | The interval for flow auto-saving in milliseconds. |
| `--backend-only` | `--no-backend-only` (false) | Boolean | Whether to run Terraflow's backend service only (no frontend). Omit or use `--no-backend-only` to start both the frontend and backend. See [Start Terraflow in headless mode](#start-terraflow-in-headless-mode). |
| `--cache` | `async` | String | The type of [cache storage](/memory) to use. One of `async`, `redis`, `memory`, or `disk`. |
| `--components-path` | Not set | String | The path to the directory containing your custom components. |
| `--dev` | `--no-dev` (false) | Boolean | Whether to run in development mode (may contain bugs). |
| `--env-file` | Not set | String | The path to the `.env` file containing Terraflow environment variables. See [Start Terraflow with a specific .env file](#start-terraflow-with-a-specific-env-file). |
| `--frontend-path` | Not set | String | The path to the frontend directory containing build files. This is only used when [contributing to the Terraflow codebase](/contributing-how-to-contribute) or developing a custom Terraflow image that includes customized frontend code. |
| `--health-check-max-retries` | `5` | Integer | The maximum number of retries for your Terraflow server's health check. |
| `--host` | `localhost` | String | The host on which the Terraflow server will run. |
| `--log-file` | `logs/terraflow.log` | String | The path to the log file for Terraflow. |
| `--log-level` | `critical` | String | The logging level as one of `debug`, `info`, `warning`, `error`, or `critical`. |
| `--log-rotation` | Not set | String | The log rotation interval, either a time duration or file size. |
| `--max-file-size-upload` | `1024` | Integer | The maximum size in megabytes for file uploads. |
| `--open-browser` | `--no-open-browser` (false) | Boolean | Whether to open the system web browser on startup. Use `--open-browser` to open the system's default web browser when Terraflow starts. |
| `--port` | `7860` | Integer | The port on which the Terraflow server will run. The server automatically selects a free port if the specified port is in use. |
| `--remove-api-keys` | `--no-remove-api-keys` (false) | Boolean | Whether to remove API keys and tokens from flows saved in the Terraflow database. |
| `--ssl-cert-file-path` | Not set | String | The path to the SSL certificate file on the local system for SSL-encrypted connections. |
| `--ssl-key-file-path` | Not set | String | The path to the SSL key file on the local system for SSL-encrypted connections. |
| `--worker-timeout` | `300` | Integer | The Terraflow server worker timeout in seconds. |
| `--workers` | `1` | Integer | The number of Terraflow server worker processes. |

#### Start Terraflow with a specific .env file {#start-terraflow-with-a-specific-env-file}

The `--env-file` option starts Terraflow using the configuration defined in the given `.env` file.

If `--env-file` is omitted or doesn't include all required variables, Terraflow uses the default values for those variables.

### terraflow superuser {#terraflow-superuser}

Creates a superuser account with the given username and password.

<Tabs groupId="Invocation">
  <TabItem value="uv (recommended)" label="uv (recommended)" default>

```bash
uv run terraflow superuser --username [NAME] --password [PASSWORD] [OPTIONS]
```

  </TabItem>
  <TabItem value="Direct" label="Direct">

```bash
terraflow superuser --username [NAME] --password [PASSWORD] [OPTIONS]
```

  </TabItem>
</Tabs>

#### Options

| Option | Default | Type | Description |
|--------|---------|--------|-------------|
| `--log-level` | `error` | String | The logging level. One of `debug`, `info`, `warning`, `error`, or `critical`. |

For this command, `--username` and `--password` aren't optional, and they have no default value.
The command fails if you don't provide these arguments.
For more information, see [`TERRAFLOW_SUPERUSER` and `TERRAFLOW_SUPERUSER_PASSWORD`](/api-keys-and-authentication#terraflow-superuser).

#### Disable CLI superuser creation

The `terraflow superuser` command is controlled by the [`TERRAFLOW_ENABLE_SUPERUSER_CLI`](/api-keys-and-authentication#terraflow-enable-superuser-cli) environment variable:

* **`TERRAFLOW_ENABLE_SUPERUSER_CLI=True` (default)**: The `terraflow superuser` command is available, and superuser creation is unrestricted.
* **`TERRAFLOW_ENABLE_SUPERUSER_CLI=False` (recommended)**: Disables the `terraflow superuser` command.
For security reasons, this is recommended to prevent unauthorized superuser creation, especially in production environments.

To disable the `terraflow superuser` command, you must set `TERRAFLOW_ENABLE_SUPERUSER_CLI=False` in your Terraflow `.env` file, and then [start Terraflow with your `.env` file](#start-terraflow-with-a-specific-env-file).
